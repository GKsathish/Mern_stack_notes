DAY 1: REACT FUNDAMENTALS
====================================================================

1. WHAT IS REACT?

Definition:
React is an open-source JavaScript library used to build fast, reusable, component-based user interfaces, especially single-page applications.

Example:
function Welcome() {
  return <h1>Hello React</h1>;
}

Use case:
Dashboards, admin panels, e-commerce websites, social media feeds, employee management systems.

Internal working:
React builds a component tree. When state or props change, React calculates the new UI using the Virtual DOM, compares it with the previous Virtual DOM, and updates only the changed parts of the real DOM. This process is called reconciliation.

Follow-up questions:
1. Is React a framework or library?
2. Why is React popular?
3. What is declarative UI?
4. What is component-based architecture?

Interview-ready answer:
React is a component-based JavaScript library for building user interfaces. It uses a Virtual DOM and reconciliation to update only the required parts of the UI, which improves performance and developer productivity.

--------------------------------------------------------------------
2. SPA VS MPA

Definition:
SPA means Single Page Application. MPA means Multi Page Application.

SPA:
- One HTML page is loaded initially.
- JavaScript updates the UI without full page reload.
- Routing is handled on the client side.
- Example: React, Angular, Vue applications.

MPA:
- Every navigation loads a new HTML page from the server.
- Browser refreshes the entire page.
- Example: Traditional websites, many PHP or server-rendered websites.

Example:
React Router changes the component based on URL without reloading the page.

Use case:
SPA is useful for dashboards, admin panels and interactive apps.
MPA is useful for content-heavy websites where SEO and simple server rendering are important.

Internal working:
In SPA, the browser downloads JavaScript. The router intercepts URL changes, renders the matching component, and calls APIs for data. The page does not fully reload.

Follow-up questions:
1. What are advantages and disadvantages of SPA?
2. How does SEO work in SPA?
3. What is client-side routing?
4. When would you choose MPA over SPA?

Interview-ready answer:
An SPA loads once and updates the UI through JavaScript without full page reloads. An MPA loads a new page for every route. I use SPA for interactive applications and MPA or SSR when SEO and initial content delivery are critical.

3. COMPONENTS AND JSX

Definition:
A component is a reusable, independent piece of UI. JSX is JavaScript XML syntax that lets us write HTML-like code inside JavaScript.

Example:
function UserCard({ name, email }) {
  return (
    <div>
      <h2>{name}</h2>
      <p>{email}</p>
    </div>
  );
}

Use case:
Buttons, cards, navbar, forms, tables, modals and pages are commonly built as components.

Internal working:
Browsers do not understand JSX directly. Babel or a modern bundler converts JSX into React.createElement calls. React uses these calls to create JavaScript objects describing the UI, then renders them into the DOM.

Example transformation:
<h1>Hello</h1>
becomes approximately:
React.createElement("h1", null, "Hello");

Follow-up questions:
1. What is the difference between functional and class components?
2. Can JSX contain if statements directly?
3. Why should JSX have one parent element?
4. What is Babel?

Interview-ready answer:
Components are reusable UI building blocks. JSX is syntax sugar for React.createElement, which describes UI as JavaScript objects. Babel compiles JSX into browser-compatible JavaScript.

--------------------------------------------------------------------
4. PROPS VS STATE

Definition:
Props are read-only inputs passed from parent to child. State is mutable data managed inside a component.

Props are read-only inputs passed from a parent component to a child component. They allow components to receive data and configuration from outside.

State is mutable data managed by a component or a state-management system that can change over time and influence the rendered UI.


Example:
function Parent() {
  const [count, setCount] = useState(0);
  return <Child count={count} />;
}

function Child({ count }) {
  return <h2>Count: {count}</h2>;
}

Use case:
Props: reusable components, configuration, data passing.
State: counters, form values, modal visibility, loading state.

Internal working:
When props or state change, React schedules a re-render of the affected component. Child components re-render when they receive new props or when their own state/context changes.

Follow-up questions:
1. Can a child modify props?
2. What is prop drilling?
3. What is lifting state up?
4. When should state be moved to a parent?

Interview-ready answer:
Props are immutable inputs from parent to child, while state is component-owned mutable data. If multiple components need the same data, we lift the state to their closest common parent and pass it down through props.

--------------------------------------------------------------------
5. ONE-WAY DATA FLOW

Definition:
In React, data flows from parent to child through props. Child components do not directly change parent data.

Example:
function Parent() {
  const [value, setValue] = useState("");
  return <Input value={value} onChange={setValue} />;
}

Use case:
Predictable data flow, easier debugging, controlled components.

Internal working:
Parent passes data and callback functions to children. Child calls the callback; parent updates state; React re-renders parent and children with updated props.

Follow-up questions:
1. How does a child update parent state?
2. Why is one-way data flow useful?
3. What is two-way binding?

Interview-ready answer:
React follows one-way data flow: parent sends props down, and children request changes through callbacks. This makes data changes predictable and easier to debug.

1. CONDITIONAL RENDERING

Definition:
Conditional rendering means showing different UI based on a condition.

Example:
{isLoggedIn ? <Dashboard /> : <Login />}

{error && <p className="error">{error}</p>}

Use case:
Show loading spinner, error message, empty state, admin-only UI, authenticated pages.

Internal working:
JavaScript expressions inside JSX are evaluated during render. false, null and undefined render nothing in JSX.

Follow-up questions:
1. Difference between && and ternary operator in JSX?
2. Why does 0 render in JSX?
3. How do you avoid rendering nothing accidentally?

Interview-ready answer:
I use ternary operators for either/or UI and && for show-or-hide UI. I ensure conditions return Boolean values because values like 0 can accidentally render in JSX.

2. LISTS AND KEYS

Definition:
 lists are used to render multiple elements dynamically from arrays or objects, making UI development efficient and reusable. 

A key serves as a unique identifier in React, helping to track which items in a list have changed, been updated, or removed. It is particularly useful when dynamically creating components or when users modify the list.


Example:
{users.map(user => (
  <li key={user.id}>{user.name}</li>
))}

Use case:
Employee lists, product lists, tables, notifications, comments.

Internal working:
During reconciliation, React uses keys to match old and new elements. Keys help React understand whether an item was added, removed, reordered or updated.

Important:
Do not use array index as key if the list can reorder, insert or delete items.

Follow-up questions:
1. Why are keys important?
2. Why should index not be used as key?
3. What happens if keys are duplicated?
4. How do keys affect state preservation?

Interview-ready answer:
Keys help React identify list items during reconciliation. Stable unique keys prevent unnecessary DOM updates and preserve component state correctly. I avoid index keys for dynamic or reorderable lists.

3. CONTROLLED VS UNCONTROLLED COMPONENTS

Definition:
In controlled components, form data is controlled by React state. In uncontrolled components, form data is handled by the DOM itself, usually using refs.

Controlled example:
const [name, setName] = useState("");
<input value={name} onChange={e => setName(e.target.value)} />

Uncontrolled example:
const nameRef = useRef();
<input ref={nameRef} />

Use case:
Controlled: validation, conditional fields, live search, dependent dropdowns.
Uncontrolled: simple forms, file inputs, integrating non-React libraries.

Internal working:
Controlled inputs update React state on every change, causing re-render. Uncontrolled inputs store value in the DOM; React reads it only when needed using ref.

Follow-up questions:
1. Which is better for validation?
2. How do you get file input value?
3. What is defaultValue?
4. What are disadvantages of controlled components?

Interview-ready answer:
Controlled components keep form values in React state and are best for validation and dynamic UI. Uncontrolled components rely on DOM refs and are useful for simple forms or file inputs.

4. COMPOSITION, LIFTING STATE AND PROP DRILLING

Definition:
Composition means building complex UI from smaller components. Lifting state means moving shared state to the closest common parent. Prop drilling means passing props through multiple intermediate components.

Example:
function App() {
  const [user, setUser] = useState(null);
  return <Layout user={user} />;
}

Use case:
Shared user data, theme, filters, selected items.

Internal working:
React does not automatically share state between siblings. The common parent owns the state and passes data/callbacks downward.

Problem:
If props pass through many unnecessary components, code becomes harder to maintain. Context API, component composition or state libraries can reduce this.

Follow-up questions:
1. How do you avoid prop drilling?
2. When should you use Context API?
3. What is component composition?

Interview-ready answer:
I lift shared state to the closest common parent. For deep prop drilling, I use composition, Context API or a state management library depending on the complexity.

5. FRAGMENTS AND SYNTHETIC EVENTS

Definition:
Fragment lets us group multiple elements without adding an extra DOM node. 

"A React Fragment is a built-in feature that allows you to group a list of children elements without adding an extra, unnecessary node to the HTML DOM. 
It enables components to return multiple root-level elements seamlessly."

SyntheticEvent is React's cross-browser wrapper around native browser events.

"A Synthetic Event in React is a cross-browser wrapper around the browser’s native event. 
It implements the exact same interface as a native DOM event—including methods like preventDefault() and stopPropagation()—but guarantees that events behave consistently across all browsers, operating through global event delegation at the root container."

Example:
<>
  <h1>Title</h1>
  <p>Description</p>
</>

<button onClick={(e) => console.log(e.target)}>Click</button>

Use case:
Fragments: avoid unnecessary div wrappers in tables and lists.
Synthetic events: handle clicks, inputs, keyboard events consistently.

Internal working:
React attaches event listeners at the root container and uses event delegation. SyntheticEvent normalizes browser differences and provides a consistent API.

Follow-up questions:
1. What is event delegation?
2. Difference between synthetic event and native event?
3. Is e.persist still needed?
4. What is event pooling?

Interview-ready answer:
Fragments group JSX without adding extra DOM nodes. SyntheticEvent is React's normalized event system built on event delegation, providing consistent behavior across browsers.

DAY 3: IMPORTANT HOOKS
====================================================================

1. useState

Definition:
useState is a React hook that adds state to functional components. 
It returns the current state and a function to update it.
syntax:
const [state, setState] = useState(initialValue);

Example:
const [count, setCount] = useState(0);
setCount(prev => prev + 1);

Use case:
Counters, form fields, toggles, loading flags, modal visibility.

Internal working:
React stores state per component instance. Calling setter schedules a re-render. React batches multiple state updates where possible.

Functional update:
Functional updates use the previous state to calculate the new state.
They are useful when the new state depends on the previous state.

setCount(prev => prev + 1)
is safer when next value depends on previous value.

Follow-up questions:
1. What is batching?
2. What is lazy initialization?
3. Does useState cause immediate re-render?
4. What happens if we set the same value again?

Batching in React is a performance optimization where React groups multiple state updates into a single re-render.

Instead of updating the user interface (UI) every single time a state variable changes, React waits until all state setters in a block of code have finished running, then processes them all at once.

Interview-ready answer:
useState manages local component state. I use functional updates when the new state depends on the previous state, especially inside event handlers or async operations.

--------------------------------------------------------------------
2. useEffect

Definition:
The useEffect Hook in React allows you to synchronize your components with an external system or handle side effects.
Examples of side effects include fetching data from an API, interacting directly with the browser DOM, setting up timers, or subscribing to external services.

Example:
useEffect(() => {
  fetch("/api/users")
    .then(res => res.json())
    .then(setUsers);
}, []);

Use case:
Fetching data, updating document title, timers, event listeners, subscriptions.

Internal working:
After React commits UI to the DOM, effects run asynchronously. The dependency array decides when the effect re-runs. The cleanup function runs before the next effect execution and when the component unmounts.

Dependency array:
[] -> run once after mount
[dep] -> run when dep changes
No array -> run after every render

Follow-up questions:
1. Why does useEffect run twice in Strict Mode?
2. What is cleanup function?
3. What causes infinite loops in useEffect?
4. Difference between useEffect and useLayoutEffect?

Interview-ready answer:
useEffect handles side effects after render. I always provide correct dependencies and cleanup functions to prevent memory leaks, duplicate requests and stale data.

--------------------------------------------------------------------
3. useLayoutEffect VS useEffect

Definition:
useEffect runs asynchronously after paint. useLayoutEffect runs synchronously after DOM mutations but before the browser paints.

Example:
useLayoutEffect(() => {
  console.log("Measure DOM before paint");
}, []);

Use case:
useLayoutEffect: measuring DOM elements, preventing visual flicker.
useEffect: API calls, subscriptions, most side effects.

Internal working:
useLayoutEffect blocks painting until it completes. It should be used sparingly because it can affect performance.

Follow-up questions:
1. When should useLayoutEffect be avoided?
2. What is paint?
3. Can useLayoutEffect cause performance issues?

Interview-ready answer:
I use useEffect for most side effects. I use useLayoutEffect only when I need to read or modify DOM layout before the browser paints, such as measuring an element to avoid flicker.

--------------------------------------------------------------------
4. useRef

Definition:
useRef returns a mutable object with a current property. It can hold a DOM reference or any mutable value without causing re-render.

Example:
const inputRef = useRef();
<input ref={inputRef} />

button onClick={() => inputRef.current.focus()}

Use case:
Focus input, scroll to element, store timer ID, store previous value, access DOM.

Internal working:
Updating ref.current does not trigger re-render. Refs persist across renders for the same component instance.

Follow-up questions:
1. Difference between useRef and useState?
2. Can useRef hold objects?
3. What is forwardRef?
4. When should refs be used?

Interview-ready answer:
useRef stores mutable values or DOM references without triggering re-render. I use it for DOM access, timers and values that should persist but do not affect UI.

--------------------------------------------------------------------
5. useMemo

Definition:
useMemo memoizes the result of an expensive calculation between renders.

Example:
const filtered = useMemo(() => {
  return users.filter(u => u.department === department);
}, [users, department]);

Use case:
Filtering large lists, heavy calculations, stable object references.

Internal working:
React stores the previous result and dependencies. If dependencies are unchanged, it returns the cached result instead of recalculating.

Follow-up questions:
1. Does useMemo always improve performance?
2. What happens with wrong dependencies?
3. Difference between useMemo and useCallback?

Interview-ready answer:
useMemo caches a calculated value. I use it only for expensive calculations or when stable object references are needed; otherwise it adds unnecessary complexity.

--------------------------------------------------------------------
6. useCallback

Definition:
useCallback memoizes a function reference between renders.

Example:
const handleClick = useCallback(() => {
  console.log("Clicked");
}, []);

Use case:
Passing callbacks to memoized child components, preventing unnecessary child renders.

Internal working:
Without useCallback, a new function is created on every render. With useCallback, React returns the same function reference until dependencies change.

Follow-up questions:
1. Why does React.memo need useCallback?
2. What are dependencies in useCallback?
3. Does useCallback improve all apps?

Interview-ready answer:
useCallback keeps the same function reference across renders. I use it with React.memo when a child would otherwise re-render due to a new callback reference.

--------------------------------------------------------------------
7. React.memo

Definition:
React.memo is a higher-order component that prevents a component from re-rendering if its props have not changed.

Example:
const UserCard = React.memo(function UserCard({ name }) {
  return <h2>{name}</h2>;
});

Use case:
Large lists, expensive child components, dashboards.

Internal working:
React performs shallow comparison of previous and next props. If props are equal, it skips rendering the child.

Limitation:
It does not prevent re-render caused by the component's own state or context changes.

Follow-up questions:
1. Does React.memo do deep comparison?
2. How to customize comparison?
3. When should we not use React.memo?

Interview-ready answer:
React.memo prevents unnecessary child renders by shallow-comparing props. I use it for expensive components and combine it with useCallback or useMemo when function or object props are involved.

DAY 4: ADVANCED HOOKS

1. CUSTOM HOOKS

Definition:
A custom hook is a JavaScript function whose name starts with use and which uses built-in React hooks to share reusable logic.

Example:
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let active = true;
    setLoading(true);

    fetch(url)
      .then(res => res.json())
      .then(result => {
        if (active) setData(result);
      })
      .finally(() => {
        if (active) setLoading(false);
      });

    return () => {
      active = false;
    };
  }, [url]);

  return { data, loading };
}

Use case:
Fetching APIs, debouncing, local storage, media queries, authentication, form handling.

Internal working:
Custom hooks do not create separate React state systems. Each component calling the custom hook gets its own independent state and effects.

Follow-up questions:
1. Can custom hooks call other custom hooks?
2. Why must custom hook names start with use?
3. How do you prevent stale responses?
4. Difference between custom hook and utility function?

Interview-ready answer:
Custom hooks reuse stateful logic across components. Each caller receives independent state, and I handle cleanup or cancellation to avoid stale updates.

2. useReducer

Definition:
useReducer is an alternative to useState for managing complex state logic using actions and a reducer function.

Example:
const [state, dispatch] = useReducer(reducer, { count: 0 });

function reducer(state, action) {
  switch (action.type) {
    case "INCREMENT":
      return { count: state.count + 1 };
    default:
      return state;
  }
}

Use case:
Cart, forms with multiple fields, complex state transitions, undo/redo.

Internal working:
dispatch sends an action to the reducer. The reducer returns new state. React re-renders the component with updated state.

Follow-up questions:
1. When do you choose useReducer over useState?
2. Can reducer be async?
3. What is an action?
4. How is useReducer related to Redux?

Interview-ready answer:
useReducer centralizes state update logic in a pure reducer function. I use it when multiple related state values or complex transitions make useState difficult to manage.

3. useContext

The Context API is a built-in React feature that allows you to share global data (such as user authentication, themes, or language preferences) across the component tree without manually passing props through every intermediate component—a problem known as prop drilling .   

Definition:
useContext lets a component read data from a React Context without passing props through every level. or 
useContextis a built-in React Hook used inside functional components to read and subscribe to data provided by a Context object.   

Example:
const ThemeContext = createContext();

<ThemeContext.Provider value="dark">
  <Child />
</ThemeContext.Provider>

const theme = useContext(ThemeContext);

Use case:
Theme, authenticated user, language, app configuration.

Internal working:
Provider supplies context value. Any consumer below it can read that value. When provider value changes, all consuming components re-render.

Follow-up questions:
1. Does Context replace Redux?
2. What is context performance issue?
3. How do you avoid unnecessary re-renders with Context?
4. Can Context hold functions?

Interview-ready answer:
useContext provides global-ish data without prop drilling. It is best for low-frequency global data such as theme or auth. For frequently changing server data or complex state, Redux Toolkit or RTK Query is usually better.

4. useId, useTransition AND useDeferredValue

useId:
Generates unique IDs for accessibility and form labels.

const id = useId();
<label htmlFor={id}>Email</label>
<input id={id} />

useTransition:
Technical definition: A React Hook that lets you mark a state update as a non-urgent transition, so urgent updates (typing, clicking) stay responsive while React renders the heavy update in the background.

import { useState, useTransition } from "react";

function Search({ items }) {
  const [input, setInput] = useState("");
  const [query, setQuery] = useState("");
  const [isPending, startTransition] = useTransition();

  function handleChange(event) {
    const value = event.target.value;

    setInput(value);

    startTransition(() => {
      setQuery(value);
    });
  }

  const results = items.filter(item =>
    item.name.toLowerCase().includes(query.toLowerCase())
  );

  return (
    <>
      <input value={input} onChange={handleChange} />
      {isPending && <p>Updating results...</p>}

      {results.map(item => (
        <p key={item.id}>{item.name}</p>
      ))}
    </>
  );
}

Real-project use case: A large search result list should not make typing feel unresponsive.

Important: useTransition does not make an expensive calculation inherently faster or debounce network requests. It allows React to prioritize rendering work.

Follow-up: Can a controlled text input's own state update be placed inside a transition?
Generally, no. The state update controlling the input value must remain urgent; transition updates are for non-urgent work.

useDeferredValue:
Technical definition: useDeferredValue lets React defer updating a value used by part of the UI, allowing more urgent updates to render first.
Technical definition: A React Hook that lets you defer updating a value used by part of the UI. React first re-renders with the old value, then re-renders in the background with the new value.

import { useDeferredValue, useMemo, useState } from "react";

function Search({ items }) {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);

  const results = useMemo(() => {
    return items.filter(item =>
      item.name.toLowerCase().includes(
        deferredQuery.toLowerCase()
      )
    );
  }, [items, deferredQuery]);

  return (
    <>
      <input
        value={query}
        onChange={event => setQuery(event.target.value)}
      />

      {results.map(item => (
        <p key={item.id}>{item.name}</p>
      ))}
    </>

  );
}
Real-project use case: The search input updates immediately while an expensive result list can update at a lower priority.

Use case:
Large lists, search filters, heavy rendering, concurrent UI.

Internal working:
These hooks support React concurrent rendering. Urgent updates such as typing happen immediately, while expensive updates can be deferred.

usetransition and usedeferedvalue are  conncurent rendering  features
Follow-up questions:
1. Difference between useTransition and useDeferredValue?
2. What is concurrent rendering?
3. When should useId be used?

Interview-ready answer:
useId creates stable unique IDs, useTransition marks updates as non-urgent, and useDeferredValue lets React render with an older value while calculating a newer one. They improve responsiveness in heavy UIs.

5. RULES OF HOOKS AND STALE CLOSURES

Rules of Hooks:
1. Call hooks only at the top level.
2. Do not call hooks inside conditions, loops or nested functions.
3. Call hooks only in React functions or custom hooks.

Stale closure:
A stale closure occurs when a function retains values from an earlier render and uses those values after the state or props have changed.

Example problem:
useEffect(() => {
  const timer = setInterval(() => {
    setCount(count + 1);
  }, 1000);
  return () => clearInterval(timer);
}, []);

Correct:
setCount(prev => prev + 1);

Use case:
Avoiding incorrect timer values, event listener bugs, async race conditions.

Internal working:
Each render creates its own function scope. If a callback captures state from an old render, it may use outdated data unless dependencies or functional updates are handled correctly.

Follow-up questions:
1. Why do stale closures happen?
2. How do you fix stale state in setInterval?
3. What are common useEffect mistakes?

Interview-ready answer:
Stale closures occur when callbacks capture old render values. I fix them using functional state updates, correct dependency arrays, refs or cleanup logic.

DAY 5: REACT INTERNALS
====================================================================

1. VIRTUAL DOM

Definition:
Virtual DOM is a lightweight JavaScript representation of the real DOM maintained by React.

Use case:
Efficient UI updates in dynamic applications.

Internal working:
1. State or props change.
2. React creates a new Virtual DOM tree.
3. React compares it with previous tree using diffing.
4. React calculates minimum DOM operations.
5. React updates only required real DOM nodes.

Follow-up questions:
1. Is Virtual DOM faster than real DOM always?
2. What is diffing?
3. What is reconciliation?

Interview-ready answer:
Virtual DOM helps React minimize direct DOM operations. React diffs the new and previous Virtual DOM trees and applies only required changes to the real DOM.

--------------------------------------------------------------------
2. RECONCILIATION AND REACT FIBER

Definition:
Reconciliation is the process of comparing the previous and new component trees to determine UI changes. React Fiber is React's reconciliation engine.

Use case:
Efficient updates, prioritized rendering, interruptible work.

Internal working:
Fiber breaks rendering work into small units. It can pause, prioritize, abort or resume work. This enables concurrent rendering features such as transitions and deferred values.

Follow-up questions:
1. What is Fiber?
2. What is interruptible rendering?
3. What is priority in React?
4. How does Fiber improve performance?

Interview-ready answer:
Fiber is React's reconciliation architecture. It makes rendering work incremental and prioritizable, allowing React to keep urgent interactions responsive while processing larger updates.

--------------------------------------------------------------------
3. RENDER PHASE VS COMMIT PHASE

Definition:
Render phase calculates what UI should look like. Commit phase applies changes to the real DOM.

Render phase:
- Component functions run.
- New Virtual DOM is created.
- Should be pure and side-effect free.

Commit phase:
- React updates the real DOM.
- useEffect runs after commit.
- Refs are attached.

Use case:
Understanding where side effects should run and why render must be pure.

Follow-up questions:
1. Why should render be pure?
2. Where do API calls belong?
3. When does useEffect run?

Interview-ready answer:
During render, React calculates UI and must not perform side effects. After commit, React updates the DOM and runs effects such as API calls, subscriptions and timers.

--------------------------------------------------------------------
4. WHY COMPONENTS RE-RENDER

Reasons:
1. Component's own state changes.
2. Parent re-renders and passes new props.
3. Context value changes.
4. Redux/store subscription changes.
5. New object, array or function references are created.

Example:
Parent re-renders and creates:
onClick={() => doSomething()}
This creates a new function reference every render, causing memoized children to re-render.

Use case:
Performance optimization and debugging.

Internal working:
React re-renders a component to calculate new UI. Re-render does not always mean real DOM update; React may find no DOM changes after diffing.

Follow-up questions:
1. Does parent re-render always update DOM?
2. How do you identify unnecessary re-renders?
3. How do you prevent child re-renders?

Interview-ready answer:
Components re-render due to state, props, context or store changes. I use React Profiler to identify unnecessary renders, then apply memoization, stable references, state splitting or component composition.

--------------------------------------------------------------------
5. KEYS, COMPONENT IDENTITY AND STATE PRESERVATION

Definition:
Keys identify elements across renders. Component identity decides whether React preserves or recreates component state.

Example:
{items.map(item => (
  <Item key={item.id} item={item} />
))}

Use case:
Dynamic lists, tabs, forms, modals.

Internal working:
If key changes, React unmounts the old component and mounts a new one, resetting its state. If key remains same, React updates the existing component and preserves state.

Follow-up questions:
1. Why does changing key reset state?
2. When is changing key useful?
3. What happens with duplicate keys?

1. createAsyncThunk

Definition:
createAsyncThunk creates Redux actions for async operations and generates pending, fulfilled and rejected lifecycle actions.

  "users/fetchUsers",

    try {
      const response = await fetch("/api/users");
      if (!response.ok) {
        const error = await response.json();
        return rejectWithValue(error.message);
      }
      return response.json();
    } catch (error) {
      return rejectWithValue(error.message);
    }
  }
);

Use case:
Fetch users, login, create product, upload file.

Internal working:
When dispatched, createAsyncThunk dispatches pending action, runs the async function, then dispatches fulfilled or rejected based on result.

Generated actions:

users/fetchUsers/fulfilled
users/fetchUsers/rejected

Important:
"users/fetchUsers" is not an API URL. It is an action type prefix. The actual API URL is inside fetch() or axios call.

3. What happens if prefix is duplicated?
4. Where is API URL defined?

Interview-ready answer:
createAsyncThunk handles async Redux logic and automatically generates pending, fulfilled and rejected actions. I use rejectWithValue to send custom error payloads, and the actual HTTP request happens inside the payload creator function.

1. ERROR BOUNDARIES VS TRY/CATCH

Error Boundary is a React component that catches rendering errors in its child tree. try/catch handles JavaScript errors in normal code execution.

    console.error(error, info);
  }

  render() {
    return this.state.hasError
      ? <h1>Something went wrong</h1>
      : this.props.children;
  }
}

Use case:
Prevent full app crash due to one broken component.

Important:
Error Boundaries do not catch errors in event handlers, async code, server-side rendering or errors thrown in the Error Boundary itself.

Follow-up questions:

Interview-ready answer:
Error Boundaries catch rendering errors in child components, while try/catch handles synchronous JavaScript errors. For async/API errors, I handle them in thunks, query hooks or async functions and show user-friendly error UI.

    fetch(`/api/users?search=${search}&page=${page}`, {
      signal: controller.signal
    })
      .then(res => res.json())
      .then(setData)
      .catch(err => {
        if (err.name !== "AbortError") setError(err.message);
      });
  }, 500);

  return () => {
    clearTimeout(timer);
    controller.abort();
  };
}, [search, page]);

QUICK REVISION: MOST ASKED ANSWERS
====================================================================

1. React is a component-based UI library using Virtual DOM and reconciliation.
2. Props flow down; state is managed within components.
3. Keys must be stable and unique for lists.
4. useEffect handles side effects after render and requires cleanup.
5. useMemo caches values; useCallback caches function references.
6. React.memo prevents child re-render when props do not change.
7. Context avoids prop drilling but can cause broad re-renders.
8. Redux Toolkit is the modern way to write Redux.
9. createAsyncThunk generates pending, fulfilled and rejected actions.
10. RTK Query manages server state with caching and request deduplication.
11. Code splitting creates chunks; lazy loading loads them when needed.
12. Virtualization renders only visible items.
13. Debouncing delays execution until inactivity.
14. Error Boundaries catch rendering errors; try/catch handles normal JS errors.
15. React Testing Library tests UI from the user's perspective.
16. Next.js supports SSR, SSG, routing and performance optimizations.
17. React escapes JSX content by default to reduce XSS risk.
18. Always validate and authorize on the backend; frontend checks are UX only.
