Javascript:

JavaScript is a high-level, dynamically typed, garbage-collected programming language primarily used to build interactive web applications. 
It supports multiple programming paradigms, including object-oriented, functional, and event-driven programming.

Features :

Single-threaded execution	                 JavaScript code normally executes on one main thread per execution context.

V8 engine:

 V8 is an open-source JavaScript and WebAssembly engine developed by Google. It compiles and executes JavaScript code using components such as the Ignition interpreter and the TurboFan optimizing compiler.

 When JavaScript runs, V8 parses and executes this code.

 Node.js uses V8 to execute your JavaScript. Node.js also provides networking and other runtime facilities used by your Express server.


 Follow-up interview questions
Q1. Is JavaScript interpreted or compiled?

Answer: Modern JavaScript engines use a combination of interpretation and just-in-time compilation. V8 uses an interpreter and optimizing compilers, so JavaScript is not accurately described as purely interpreted.

Q2. Is V8 responsible for the event loop?

Answer: Not entirely. V8 provides JavaScript execution and features such as garbage collection. In Node.js, the event loop and many asynchronous I/O mechanisms are provided by Node.js and its underlying runtime components, including libuv.

Q3. Does JavaScript run only in browsers?

Answer: No. It runs in browsers and server-side environments such as Node.js, as well as other JavaScript runtimes.



Execution Context:


An execution context is the environment in which JavaScript code is evaluated and executed. It contains the information required to execute code, including its lexical environment, variable bindings, and execution state.

JavaScript commonly involves these execution contexts:
- Global Execution Context (GEC): Created to execute the program's top-level code.
- Function Execution Context (FEC): Created when a function is invoked.
- Eval Execution Context: Associated with executing code through eval(); it is rarely relevant in normal application development.


var company = "Google";

function greet() {
  var message = "Hello";
  console.log(message);
}

greet();

Execution flow:
1. JavaScript creates the global execution context.
2. Global declarations and bindings are established.
3. The global code starts executing.
4. When greet() is called, a function execution context is created.
5. The function executes and prints "Hello".
6. The function finishes, and its context is removed from the active call stack.


How execution context works
Each execution context has an associated environment for resolving variables and functions. During function execution, JavaScript uses the lexical environment to resolve identifiers, including variables from outer scopes.


Follow-up questions
Q1. When is the global execution context created?

When JavaScript starts evaluating a script or module, the relevant global or module environment is established. Module code has its own module scope.

Q2. Is an execution context the same as a call stack?

No. An execution context represents the environment for executing code. The call stack tracks active execution contexts.

Q3. Does every function call create a new execution context?

Normally, yes. Each invocation gets its own execution state and bindings, although engines may optimize their implementation internally.

Memory Heap:

The memory heap is a memory area used by the JavaScript engine to store dynamically allocated objects and other data. 
JavaScript engines manage allocation and garbage collection internally.



stack memory:

In JavaScript, stack memory is a fast, fixed-size memory region that stores static data, including primitive values and references to objects.


 memory leak:

A memory leak occurs when memory is retained even though the application no longer needs it.
Common causes include:
- Event listeners that are never removed.
- Timers that continue running unnecessarily.
- Long-lived references to large objects.
- Caches that grow without limits.

Follow-up questions
Q1. Is JavaScript pass-by-reference?

JavaScript is pass-by-value. When an object is passed to a function, the value being copied is the reference to that object. The function can mutate the shared object, but reassigning its parameter does not reassign the caller's variable.

A shallow copy duplicates the outer object but keeps nested object references shared. A deep copy duplicates nested data as well, subject to the copying method's supported types.

var vs let vs const:

Interview definition
var, let, and const are declarations used to create bindings in JavaScript.
- var is function-scoped, or globally scoped when declared at the top level of a classic script, and can be redeclared within the same scope.
- let is block-scoped and can be reassigned and cannot be reinitilized.
- const is block-scoped and cannot be reassigned after initialization.


Scope:

Scope determines where a variable or function binding can be accessed in JavaScript code. or scope determines the accessibility and visibility of variables, functions, and objects in different parts of your code.


Main types:
- Global scope
- Function scope
- Block scope
- Module scope


lexical scope:

Lexical scope means variable access is determined by where functions and blocks are written in the source code, rather than where functions are called.


const name = "Global";

function outer() {
  const name = "Outer";

  function inner() {
    console.log(name);
  }

  inner();
}

outer(); // Outer


inner() accesses the name from its lexical parent, outer().

Real-time use case: Closures, callbacks, React event handlers, and functions that access component-scope variables.




hoisting:


Hoisting describes the behavior in which JavaScript establishes declarations and bindings before executing the relevant code. The exact behavior depends on the declaration type.

Temporal Dead Zone:

The Temporal Dead Zone is the period from entering the relevant lexical scope until a let, const, or class binding is initialized. Accessing the binding during that period throws a ReferenceError.


Follow-up interview question
Q. Are let and const hoisted?

Yes. Their bindings are established as part of lexical environment setup, but they remain inaccessible during the TDZ until initialization. Saying they are “not hoisted” is an oversimplification.

A closure is a feature in JavaScript where an inner function retains access to the variables of its outer (enclosing) function, even after the outer function has finished executing.

A closure is the combination of a function and its lexical environment, allowing the function to access variables from its outer scope even after the outer function has finished executing.


Real-time use case: Closures can preserve state, support function factories, and help implement private internal state. In React, they are also relevant to understanding callbacks and stale state.

1. Function Declaration vs Expression; Arrow vs Regular Functions

Function Declaration

Interview definition: A function declaration defines a named function using the function keyword. Its declaration is initialized in a way that allows it to be called before its textual position in the same applicable scope.


greet();

function greet() {
  console.log("Hello");
}

// Output: Hello


Real-time use case: Defining reusable business logic, utility functions and API validation functions in a Node.js application.


Function Expression:

Interview definition: A function expression creates a function as part of an expression and assigns or passes that function as a value. The variable's declaration rules determine when it can be accessed.
// greet(); // ReferenceError

const greet = function () {
  console.log("Hello");
};

greet(); // Hello


Difference
Function declaration                                                            Function expression
Declared using a function declarations                               Created as part of an expression
Can generally be called before its declaration                    Calling before initialization can fail
Commonly used for named reusable functions                   Useful for callbacks and assigning functions dynamically

Regular function:

 A function defined using function. Its this value depends on how it is called, unless it is bound explicitly.

Arrow function: 

A shorter function syntax that inherits this from its surrounding lexical environment. It does not have its own this or arguments binding and cannot be used as a constructor.

function add(a, b) {
  return a + b;
}

const multiply = (a, b) => a * b;

console.log(add(2, 3));      // 5
console.log(multiply(2, 3)); // 6


const user = {
  name: "Ravi",

  regular() {
    return this.name;
  },

  arrow: () => this.name
};

console.log(user.regular()); // Ravi
console.log(user.arrow());   // Usually undefined in a non-module browser script


The arrow function does not get this from user. Its this comes from the surrounding scope, so its result depends on that environment.

Real-time React use case: Arrow functions are commonly used for event handlers and callbacks.
function UserButton() {
  const handleClick = () => {
    console.log("Button clicked");
  };

  return <button onClick={handleClick}>Click</button>;
}


Follow-up interview questions
Q1. Can arrow functions be constructors?

No. Arrow functions cannot be called with new.

Q2. Do arrow functions have their own arguments?

No. They inherit access to arguments from the enclosing non-arrow function, if one exists. Use rest parameters when you need to collect arguments.

Q3. Does an arrow function always execute faster?

No. Choose function syntax based on behavior, readability and requirements, not an assumption that arrows are always faster.


What is this?

Interview definition: 
this is a value available in a function's execution context. In regular functions, it is generally determined by the call site. Arrow functions inherit this lexically.

const user = {
  name: "Ravi",
  greet() {
    console.log(this.name);
  }
};

user.greet(); // Ravi


What is call()?
call() invokes a function immediately with a specified this value and individual arguments.
function greet(city) {
  console.log(`${this.name} from ${city}`);
}

const user = { name: "Ravi" };

greet.call(user, "Hyderabad");
// Ravi from Hyderabad


2.2 What is apply()?
apply() invokes a function immediately with a specified this value and arguments supplied as an array-like object.
greet.apply(user, ["Hyderabad"]);
// Ravi from Hyderabad


2.3 What is bind()?
bind() returns a new function with a specified this value and optionally pre-filled arguments. It does not invoke the function immediately.
const boundGreet = greet.bind(user, "Hyderabad");

boundGreet();
// Ravi from Hyderabad



3. Closures, Higher-Order Functions and Callbacks

 Closure:

Interview definition: A closure is a function that retains access to variables from its lexical environment, even after the outer function has finished executing.

function counter() {
  let count = 0;

  return function () {
    count++;
    return count;
  };
}

const increment = counter();

console.log(increment()); // 1
console.log(increment()); // 2
console.log(increment()); // 3


How it works:
1. counter() creates the local variable count.
2. It returns an inner function.
3. The inner function retains access to count.
4. Each call updates the same preserved variable.

Real-time use cases:
- Maintaining private state.
- Creating reusable function factories.
- Implementing callbacks and event handlers.
- Understanding stale closures in React hooks.

Higher-order Function:

Interview definition: A higher-order function is a function that accepts another function as an argument, returns a function, or does both.

function calculate(a, b, operation) {
  return operation(a, b);
}

const add = (a, b) => a + b;
const multiply = (a, b) => a * b;

console.log(calculate(5, 3, add));      // 8
console.log(calculate(5, 3, multiply)); // 15


Real-time use case: Array methods such as map(), filter() and reduce() accept callback functions. Middleware and reusable utilities also commonly use higher-order functions.


Callbakc Function:

Interview definition: A callback is a function passed to another function so that it can be invoked by that function, either immediately or later.
function processUser(name, callback) {
  console.log("Processing:", name);
  callback();
}

processUser("Ravi", () => {
  console.log("Completed");
});


Output:
Processing: Ravi
Completed


Callbacks can be synchronous or asynchronous.

Real-time Node.js use case:

const fs = require("node:fs");

fs.readFile("data.txt", "utf8", (error, data) => {
  if (error) {
    console.error(error);
    return;
  }

  console.log(data);
});


The callback runs when the file-reading operation completes or fails.

Follow-up interview questions
Q1. What is callback hell?

Callback hell is deeply nested callback-based code that becomes difficult to read, maintain and handle errors in. Named functions, Promises and async/await can improve readability.

Q2. What is the difference between a callback and a higher-order function?

A callback is the function being passed. A higher-order function is the function that accepts or returns functions.

Q3. What is a stale closure in React?

It occurs when a callback uses values captured from an earlier render instead of the latest values.
useEffect(() => {
  const id = setInterval(() => {
    console.log(count);
  }, 1000);

  return () => clearInterval(id);
}, []);




4. Pure Functions, Side Effects, IIFE, Currying and Composition


Pure Functions

Interview definition: A pure function returns the same output for the same inputs and has no observable side effects.
function add(a, b) {
  return a + b;
}

console.log(add(2, 3)); // 5
console.log(add(2, 3)); // 5


The result depends only on the inputs.

What is a side effect?
A side effect occurs when a function interacts with or changes state outside its own return value.

Examples include:
- Updating a database.
- Modifying a global variable.
- Making an HTTP request.
- Writing to a file.
- Updating the DOM directly.
let total = 0;

function addToTotal(value) {
  total += value; // Side effect
}


Real-time use case: Keeping calculation and validation functions pure makes them easier to test. 
Database writes and HTTP requests belong in the appropriate service or effect layer.


4.2 What is an IIFE?

Interview definition: An Immediately Invoked Function Expression (IIFE) is a function expression that is executed immediately after it is defined.
(function () {
  const message = "Initialized";
  console.log(message);
})();

// Output: Initialized


An arrow-function IIFE is also possible:
(() => {
  console.log("Started");
})();


Use case: Creating a local scope and executing initialization logic. IIFEs were especially useful before ES modules became common.

4.3 What is currying?

Interview definition: Currying transforms a function that accepts multiple arguments into a sequence of functions, each accepting one argument.

function multiply(a) {
  return function (b) {
    return a * b;
  };
}

console.log(multiply(5)(3)); // 15


A reusable specialized function can be created:
const multiplyByTwo = multiply(2);

console.log(multiplyByTwo(10)); // 20
console.log(multiplyByTwo(20)); // 40


Real-time use case: Creating reusable validators, configurable utilities and functions with preset parameters.

4.4 What is function composition?
Interview definition: Function composition combines smaller functions so that the output of one function becomes the input of another.

const double = x => x * 2;
const addThree = x => x + 3;

const result = addThree(double(5));

console.log(result); // 13


Execution order is:
1. double(5) returns 10.
2. addThree(10) returns 13.
A reusable composition helper can be written as:
const compose = (f, g) => x => f(g(x));

const calculate = compose(addThree, double);

console.log(calculate(5)); // 13


Real-time use case: Composing transformations, validation functions and reusable processing steps.

Follow-up interview question

Q. Why are pure functions easier to test?

They produce predictable outputs without relying on external state, making unit tests simpler and more reliable.



5. Recursion, Rest/Spread, Destructuring and Default Parameters 


What is recursion?

Interview definition: Recursion is a programming technique in which a function calls itself to solve a problem by reducing it to smaller subproblems.
A recursive function needs a base case to stop the recursion.

function factorial(n) {
  if (n <= 1) return 1; // Base case

  return n * factorial(n - 1);
}

console.log(factorial(5)); // 120


Real-time use case: Traversing nested categories, directory structures and tree-shaped data.

Follow-up: What happens without a base case?

The recursion may continue until the call stack limit is exceeded. 


5.2 What is the rest operator?

The rest syntax collects remaining values into an array or object.
The rest parameter (...) allows a function to accept any number of arguments and collect them into a single array, making functions more flexible and dynamic.



function sum(...numbers) {
  return numbers.reduce((total, n) => total + n, 0);
}

console.log(sum(1, 2, 3, 4)); // 10


Here, numbers is an array containing all the arguments.
use cases : 
Array Destructuring
const scores = [95, 88, 76, 64, 52];

// Extracting the top two scores, and grouping the rest
const [gold, silver, ...theRest] = scores;

console.log(gold);    // Output: 95
console.log(silver);  // Output: 88
console.log(theRest); // Output: [76, 64, 52]


Object Destructuring
const user = {
  id: 101,
  username: "coder123",
  email: "coder@example.com",
  role: "admin"
};

// Separating the username out, while gathering the remaining data
const { username, ...profileData } = user;

console.log(username);    // Output: "coder123"
console.log(profileData); // Output: { id: 101, email: "coder@example.com", role: "admin" }



5.3 What is the spread operator?

Spread syntax expands iterable values or enumerable object properties into another expression.

The JavaScript spread operator (...) allows you to expand or "unpack" an iterable (like an array, object, or string) into individual elements. Introduced in ES6, it provides a clean, concise syntax for copying, merging, and passing data structures.

const first = [1, 2];
const second = [3, 4];

console.log([...first, ...second]);
// [1, 2, 3, 4]


Object spread:
const user = { name: "Ravi", age: 28 };

const updatedUser = {
  ...user,
  age: 29
};

console.log(updatedUser);
// { name: "Ravi", age: 29 }
• Copying Arrays: Creates an independent copy of an array so changes don't affect the original.
• Copying Objects: Creates a shallow clone of an object to safely modify properties.
• Merging Arrays: Combines two or more distinct arrays into a single new list.
• Merging Objects: Blends multiple objects together, automatically updating overlapping keys.
• Function Arguments: Feeds an array of numbers directly into functions like Math.max() or Math.min().
• String to Array: Breaks down a text string into an array of individual character letters.
• Removing Duplicates: Expands a unique Set back into a cleaned array with no repeat values.
• DOM Node Conversion: Converts browser element lists (NodeLists) into real arrays to use .map() or .filter().
• React State Updates: Updates a specific nested property in a state object without destroying existing data.


Important: Object and array spread make shallow copies, not automatic deep copies.

5.4 What is destructuring?

Destructuring extracts values from arrays or properties from objects into variables.

const user = {
  name: "Ravi",
  age: 28
};

const { name, age } = user;

console.log(name); // Ravi
console.log(age);  // 28


Array destructuring:
const colors = ["red", "blue"];

const [first, second] = colors;

console.log(first);  // red
console.log(second); // blue


Real-time React use case:

function UserCard({ name, age }) {
  return <p>{name} is {age} years old.</p>;
}


The component destructures its props.

5.5 What are default parameters?

Default parameters provide a value when an argument is omitted or explicitly passed as undefined.

function greet(name = "Guest") {
  return `Hello, ${name}`;
}

console.log(greet());          // Hello, Guest
console.log(greet(undefined)); // Hello, Guest
console.log(greet(null));      // Hello, null


Follow-up: Does a default parameter apply to null?

No. It applies when the argument is omitted or undefined, not when it is null.



6. Shallow vs Deep Copy; Object.freeze() vs Object.seal()

What is a shallow copy?

Interview definition: A shallow copy creates a new outer object while retaining references to the original object's nested objects.
const original = {
  name: "Ravi",
  address: { city: "Hyderabad" }
};

const copy = { ...original };

copy.name = "Krishna";
copy.address.city = "Chennai";

console.log(original.name);         // Ravi
console.log(original.address.city); // Chennai


The top-level name property is independent, but the nested address object is shared.


6.2 What is a deep copy?
Interview definition: A deep copy creates an independent copy of an object's nested data, to the extent supported by the copying method.

For supported data types, modern JavaScript provides structuredClone().

const original = {
  name: "Ravi",
  address: { city: "Hyderabad" }
};

const copy = structuredClone(original);

copy.address.city = "Chennai";

console.log(original.address.city); // Hyderabad
console.log(copy.address.city);     // Chennai


structuredClone() supports many built-in data types and circular references, but it does not clone every kind of value. For example, functions cannot be structured-cloned.

Shallow vs deep copy

Shallow copy                                                          Deep copy
Copies the outer object                                         Copies nested data as well
Nested references may be shared                        Supported nested data is independently copied
Usually less expensive                                          Can require more memory and processing
Spread syntax and Object.assign()                       structuredClone() for supported data


Real-time React use case: When updating nested state, copy each level that changes so the original state is not mutated.

setUser(previous => ({
  ...previous,
  address: {
    ...previous.address,
    city: "Chennai"
  }
}));


6.3 What is Object.freeze()?

Interview definition: Object.freeze() prevents an object's own properties from being added, removed or reconfigured, and makes its existing data properties non-writable.
const user = { name: "Ravi" };

Object.freeze(user);

user.name = "Krishna";
user.age = 28;

console.log(user); // { name: "Ravi" }


In non-strict mode, attempted changes may fail silently. In strict mode, invalid modifications generally throw a TypeError.

6.4 What is Object.seal()?

Interview definition: Object.seal() prevents adding or removing an object's own properties and prevents reconfiguring them, but existing writable properties can still be updated.
const user = { name: "Ravi" };

Object.seal(user);

user.name = "Krishna"; // Allowed
user.age = 28;         // Not added
delete user.name;      // Not deleted

console.log(user);
// { name: "Krishna" }


Freeze vs seal
Operation                                                             Object.freeze()        Object.seal()
Add properties                                                      No                           No
Delete properties                                                  No                           No
Reconfigure properties                                         No                           No
Update existing writable data properties              No                           Yes
Deeply protects nested objects automatically      No                            No

Important interview point: Both methods are shallow. Nested objects can still be mutated unless they are separately protected.
Follow-up questions

Q1. How can you check whether an object is frozen or sealed?

Object.isFrozen(user);
Object.isSealed(user);


Q2. Does Object.freeze() make an entire nested object immutable?

No. It freezes only the object passed to it, not nested objects automatically.



7. map(), filter(), reduce(), forEach(), find(), some() and every()



map()

Definition: Creates a new array by applying a callback to each element of the original array.
const result = numbers.map(n => n * 2);

console.log(result);
// [2, 4, 6, 8, 10]


Use case: Transforming API data into a format suitable for displaying in a React component.

7.2 filter()

Definition: Creates a new array containing elements that satisfy a condition.
const result = numbers.filter(n => n > 3);

console.log(result);
// [4, 5]


Use case: Filtering products by category, status or price.

7.3 reduce()
Definition: Processes array elements to accumulate a single result or another accumulated value.
const total = numbers.reduce((sum, n) => sum + n, 0);

console.log(total); // 15


Use case: Calculating shopping-cart totals, grouping records or counting items.

7.4 forEach()

Definition: Executes a callback for each array element. It returns undefined.
numbers.forEach(n => {
  console.log(n);
});


Use case: Performing an action for each item, such as logging or invoking a function.

Unlike map(), forEach() is not intended to create a transformed array.

7.5 find()

Definition: Returns the first element that satisfies a condition, or undefined if none matches.

const result = numbers.find(n => n > 3);

console.log(result); // 4


Use case: Finding a particular user, product or order in an array.

7.6 some()
Definition: Returns true if at least one element satisfies the condition.

Q1. Does map() mutate the original array?

No. It creates a new array, although the callback can still mutate objects referenced by the elements if written to do so.

Q2. Can forEach() be stopped with break?

No. A normal forEach() callback cannot be exited with break. Use a for...of loop when early termination is needed.

Q3. What happens when reduce() is used without an initial value?

The first element becomes the initial accumulator, and iteration starts at the second element. On an empty array without an initial value, reduce() throws a TypeError. Providing an initial value is often safer.

10. Map, Set, WeakMap and WeakSet
These are built-in JavaScript collection types.
10.1 What is a Map?
Interview definition: A Map stores key-value pairs and allows keys of any value type, including objects. It preserves insertion order and provides methods such as set(), get(), has() and delete().
const userRoles = new Map();

userRoles.set("Ravi", "Admin");
userRoles.set("Priya", "User");

console.log(userRoles.get("Ravi")); // Admin
console.log(userRoles.has("Priya")); // true
console.log(userRoles.size); // 2


Use case: Storing lookup data, caching results and associating objects with metadata.
10.2 What is a Set?
Interview definition: A Set stores unique values and preserves their insertion order.
const numbers = new Set([1, 2, 2, 3, 3, 4]);

console.log([...numbers]);
// [1, 2, 3, 4]


Use case: Removing duplicates and tracking unique IDs or selected items.
const ids = [101, 102, 101, 103];

const uniqueIds = [...new Set(ids)];

console.log(uniqueIds);
// [101, 102, 103]


10.3 What is a WeakMap?
Interview definition: A WeakMap stores key-value pairs whose keys must be objects or non-registered symbols. Object keys are held weakly, so the collection does not keep an otherwise unreachable key object alive by itself.
const metadata = new WeakMap();

let user = { name: "Ravi" };

metadata.set(user, { lastViewed: Date.now() });

console.log(metadata.get(user));


A WeakMap is not enumerable and does not expose a size property.

Use case: Associating private metadata with objects without making the collection itself keep those objects alive.
10.4 What is a WeakSet?
Interview definition: A WeakSet stores unique object or non-registered symbol values using weak references. It is not enumerable.
const processedUsers = new WeakSet();

const user = { name: "Ravi" };

processedUsers.add(user);

console.log(processedUsers.has(user)); // true


Use case: Tracking whether particular objects have been processed without strongly retaining them solely through the collection.

Follow-up interview questions
Q1. Why use a Map instead of an ordinary object?

A Map supports keys of any value type, provides convenient collection methods and preserves insertion order. An ordinary object is often better for simple records with string or symbol property keys.

Q2. Why can't you iterate over a WeakMap?

Its keys can be garbage-collected independently, so it does not expose enumeration methods or a size property.

Q3. Does using WeakMap guarantee that memory is immediately freed?

No. Garbage collection timing is managed by the JavaScript engine, and other strong references may still keep an object alive.

2. Promise Chaining, async/await and try/catch
2.1 What is Promise chaining?
Interview definition: Promise chaining is the process of connecting multiple .then() handlers, where each handler returns a value or Promise that determines the next Promise in the chain.

Example:
fetchUser()
  .then((user) => {
    console.log(user);
    return fetchOrders(user.id);
  })
  .then((orders) => {
    console.log(orders);
    return orders.length;
  })
  .then((count) => {
    console.log("Total orders:", count);
  })
  .catch((error) => {
    console.log("Error:", error);
  });


How does chaining work?
1. fetchUser() returns a Promise.
2. First .then() receives the user.
3. It returns the Promise from fetchOrders().
4. The next .then() waits for that returned Promise.
5. .catch() handles an error propagated through the chain.
Important interview point: Every .then() returns a new Promise.
2.2 What is async/await?
Interview definition: async/await is syntactic sugar built on Promises that allows asynchronous code to be written in a more readable, sequential style.
- An async function always returns a Promise.
- await pauses the execution of the surrounding async function until the awaited Promise settles.
- It does not block the JavaScript main thread.
Example:
async function getUser() {
  const user = await fetchUser();

  const orders = await fetchOrders(user.id);

  return orders;
}

getUser().then(console.log);


What happens internally?
When JavaScript encounters await, the async function suspends its execution. Once the awaited Promise settles, execution resumes through Promise-based scheduling.
2.3 What is try/catch?
Interview definition: try/catch is a JavaScript error-handling mechanism that allows exceptions thrown during execution to be caught and handled.

With async/await:
async function getUserData() {
  try {
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/users/1"
    );

    if (!response.ok) {
      throw new Error("API request failed");
    }

    const data = await response.json();

    console.log(data);
  } catch (error) {
    console.log("Error:", error.message);
  }
}

getUserData();


Important: The Fetch API does not automatically reject its Promise for HTTP errors such as 404 or 500. Check response.ok when appropriate.
Promise chaining vs async/await
Promise chaining  async/await
Uses .then() and .catch() Uses async and await
Can become nested with complex flows  Often easier to read
Error handling through .catch() Error handling through try/catch
Returns Promises  Async functions always return Promises

Real-time React use case
import { useEffect, useState } from "react";

function Users() {
  const [users, setUsers] = useState([]);

  useEffect(() => {
    async function loadUsers() {

  }, []);

}

Normally, await must be inside an async function. Modern JavaScript also supports top-level await in ES modules.

Q2. Does async always mean asynchronous execution?

No. The synchronous statements inside an async function execute immediately until the function reaches an await or returns.

Q3. What happens if an async function throws an error?

Its returned Promise becomes rejected.

3. Promise.all(), allSettled(), race() and any()
These four Promise methods are very important for experienced JavaScript interviews.
3.1 Promise.all()
Interview definition: Promise.all() accepts an iterable of Promises and returns a single Promise that fulfills when all input Promises fulfill. It rejects as soon as one input rejects.
const p1 = Promise.resolve("User");
const p2 = Promise.resolve("Orders");
const p3 = Promise.resolve("Payments");

Promise.all([p1, p2, p3])
  .then(result => {
    console.log(result);
  })
  .catch(error => {
    console.log(error);
  });


Output:
["User", "Orders", "Payments"]


If any Promise rejects, the resulting Promise rejects.

Real-time use case: Fetching independent data required to render a dashboard.
const [users, products, orders] = await Promise.all([
  fetchUsers(),
  fetchProducts(),
  fetchOrders()
]);


All three operations are started without waiting for the previous one.
3.2 Promise.allSettled()
Interview definition: Promise.allSettled() waits until every input Promise settles, regardless of whether it fulfills or rejects. It returns an array describing each result.
const promises = [
  Promise.resolve("Success"),
  Promise.reject("Failed"),
  Promise.resolve("Completed")
];

Promise.allSettled(promises).then(results => {
  console.log(results);
});


Output:
[
  { status: "fulfilled", value: "Success" },
  { status: "rejected", reason: "Failed" },
  { status: "fulfilled", value: "Completed" }
]


Real-time use case: Loading several independent dashboard widgets where one API failure should not prevent displaying the others.
3.3 Promise.race()
Interview definition: Promise.race() returns a Promise that settles with the outcome of the first input Promise to settle, whether fulfilled or rejected.
const p1 = new Promise(resolve => {
  setTimeout(() => resolve("First"), 1000);
});

const p2 = new Promise(resolve => {
  setTimeout(() => resolve("Second"), 2000);
});

Promise.race([p1, p2]).then(console.log);


Output after approximately one second:
First


Real-time use case: Implementing a timeout race or selecting the first completed result. Remember that racing does not automatically cancel the other operations.
3.4 Promise.any()
Interview definition: Promise.any() fulfills as soon as the first input Promise fulfills. It rejects with an AggregateError only when all input Promises reject.
const p1 = Promise.reject("Server 1 failed");
const p2 = Promise.resolve("Server 2 success");
const p3 = Promise.resolve("Server 3 success");

Promise.any([p1, p2, p3])
  .then(console.log)
  .catch(console.log);


Output:
Server 2 success


Promise methods comparison
Method  When does it settle?  Failure behavior
Promise.all() All fulfill, or one rejects Rejects on first rejection
Promise.allSettled()  All settle  Returns all outcomes
Promise.race()  First input settles Adopts first outcome
Promise.any() First input fulfills, or all reject Rejects with AggregateError if all fail

Important interview example
const p1 = Promise.reject("Error 1");
const p2 = Promise.reject("Error 2");

Promise.any([p1, p2])
  .catch(error => {
    console.log(error instanceof AggregateError); // true
    console.log(error.errors); // ["Error 1", "Error 2"]
  });


Follow-up question:

Q. What is the difference between Promise.race() and Promise.any()?

race() considers the first settled Promise, whether fulfilled or rejected. any() considers the first fulfilled Promise and ignores individual rejections until all inputs reject.

4. Event Loop; Microtasks vs Macrotasks
Very important interview topic
4.1 What is the event loop?
Interview definition: The event loop is a scheduling mechanism that coordinates JavaScript execution with queued asynchronous callbacks, allowing JavaScript to process asynchronous operations without blocking the main execution thread while those operations are pending.
Important components
1. Call Stack: Executes synchronous JavaScript functions.
2. Web APIs: Browser facilities that handle operations such as timers and DOM events.
3. Task Queue: Holds tasks such as timer callbacks and many event callbacks.
4. Microtask Queue: Holds Promise reaction callbacks and queueMicrotask() callbacks.
5. Event Loop: Coordinates when queued work can execute.
How does the event loop work?







dev.to


Simplified browser execution flow:
1. Execute synchronous code on the call stack.
2. Asynchronous operations are handled by appropriate browser facilities.
3. When operations complete, their callbacks are scheduled in the relevant queues.
4. After the current JavaScript execution completes, the microtask queue is processed.
5. The browser can then proceed with rendering and later tasks.
The exact scheduling details differ between browsers and Node.js.
4.2 What are microtasks?
Interview definition: Microtasks are high-priority queued jobs processed after the current JavaScript execution completes and before the event loop proceeds to the next task in the browser's usual scheduling model.

Examples:
- Promise .then(), .catch() and .finally() handlers.
- queueMicrotask().
- MutationObserver callbacks in browsers.
4.3 What are macrotasks (tasks)?
Interview definition: Tasks are scheduled units of work processed by the event loop, such as timer callbacks and many event callbacks.

Examples:
- setTimeout()
- setInterval()
- Browser event callbacks.
- Many I/O-related callbacks.
Microtasks vs macrotasks
Microtasks  Tasks (often called macrotasks)
Promise handlers  setTimeout
queueMicrotask  setInterval
MutationObserver  DOM events
Processed at microtask checkpoints  Processed as event-loop tasks
Drained before the next task in normal browser scheduling Run when selected by the event loop

Follow-up interview questions
Q1. Does setTimeout(fn, 0) execute immediately?

No. It schedules a timer callback for a later task. It cannot execute until the current JavaScript execution and required microtask processing allow it.

Q2. Can microtasks block rendering?

Yes. If microtasks keep scheduling more microtasks, the queue may not become empty, delaying rendering and other tasks.

Q3. Is JavaScript single-threaded even with asynchronous operations?

JavaScript execution is normally single-threaded per execution context, but browsers and Node.js use runtime facilities and other threads for certain operations.

6. Node.js process.nextTick()
Important for MERN interviews
What is process.nextTick()?
Interview definition: process.nextTick() is a Node.js API that schedules a callback to execute after the current JavaScript operation completes, before the event loop continues to its next phase.

It is specific to Node.js.
Example
console.log("Start");

process.nextTick(() => {
  console.log("Next Tick");
});

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("End");


Output in a normal CommonJS Node.js execution:
Start
End
Next Tick
Promise


Why does nextTick execute before Promise?
In Node.js, the next-tick queue is processed before the regular Promise microtask queue at the relevant checkpoint.
process.nextTick() vs Promise.then()
process.nextTick()  Promise.then()
Node.js-specific API  Standard JavaScript Promise API
Uses Node.js next-tick queue  Uses Promise microtask queue
Usually processed before Promise microtasks in Node.js  Processed in the microtask queue
Can starve the event loop if recursively scheduled  Can also starve the event loop if recursively scheduled

Real-time use case
It can be used to schedule a callback after the current operation finishes, before normal event-loop progression.

However, avoid recursive process.nextTick() scheduling because it can prevent the event loop from progressing.
Follow-up interview questions
Q1. Is process.nextTick() available in browsers?

No. It is a Node.js API.

Q2. Is process.nextTick() the same as queueMicrotask()?

No. They are separate scheduling mechanisms. Node.js processes its next-tick queue before regular Promise microtasks at the relevant checkpoints.

Q3. Which one should we prefer?

For general microtask scheduling, prefer queueMicrotask() when appropriate. Use process.nextTick() when a Node.js API specifically requires its scheduling behavior.

7. Sequential vs Parallel API Calls
This is a very common practical interview question in React and Node.js.
7.1 What are sequential API calls?
Interview definition: Sequential execution means one asynchronous operation is awaited before starting the next operation.

Example:
async function getData() {
  const user = await fetchUser();

Not directly when the second request needs the first request's result. First fetch the required data, then start the dependent request.

The returned Promise rejects when an input rejects. Other already-started operations are not automatically cancelled.

8. AbortController, Cancellation and Timeout Handling
Important React practical topic
8.1 What is AbortController?
Interview definition: AbortController is a JavaScript API used to communicate cancellation requests to asynchronous operations that support AbortSignal.

It is commonly used with the Fetch API to cancel HTTP requests.

Example
const controller = new AbortController();

fetch("/api/users", {
  signal: controller.signal
})
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => {
    if (error.name === "AbortError") {
      console.log("Request cancelled");
    } else {
      console.log(error);
    }
  });

// Cancel the request
controller.abort();


How does it work?
1. Create an AbortController.
2. Pass its signal to the asynchronous operation.
3. Call controller.abort() when cancellation is needed.
4. The operation receives the abort signal.
5. Fetch rejects with an abort-related error.
8.2 What is request cancellation?
Interview definition: Request cancellation means stopping an in-progress operation when it is no longer required, provided the operation supports cancellation.

Real-time React use cases:
- User changes search text before the previous request completes.
- Component unmounts while an API request is pending.
- User navigates to another page.
- A request exceeds its allowed time.
React example: Cleanup API request
import { useEffect, useState } from "react";

function Users() {
  const [users, setUsers] = useState([]);

  useEffect(() => {
    const controller = new AbortController();

    async function loadUsers() {
      try {
        const response = await fetch("/api/users", {
          signal: controller.signal
        });

        if (!response.ok) {
          throw new Error("Failed to fetch users");
        }

        const data = await response.json();
        setUsers(data);
      } catch (error) {
        if (error.name === "AbortError") {
          console.log("Request cancelled");
        } else {
          console.error(error);
        }
      }
    }

    loadUsers();

    return () => {
      controller.abort();
    };
  }, []);

  return <div>{users.length} users</div>;
}


Explanation: When the effect is cleaned up, the controller aborts the pending fetch. This is useful when the component unmounts or the effect is restarted.

8.3 How to implement API timeout handling?
You can combine AbortController with setTimeout().
async function fetchWithTimeout(url, timeout = 5000) {
  const controller = new AbortController();

  const timer = setTimeout(() => {
    controller.abort();
  }, timeout);

  try {
    const response = await fetch(url, {
      signal: controller.signal
    });

    if (!response.ok) {
      throw new Error(`HTTP Error: ${response.status}`);
    }

    return await response.json();
  } catch (error) {
    if (error.name === "AbortError") {
      throw new Error("Request timed out or was cancelled");
    }

    throw error;
  } finally {
    clearTimeout(timer);
  }
}


Usage:
fetchWithTimeout("/api/users", 5000)
  .then(data => console.log(data))
  .catch(error => console.log(error.message));


Important interview point
A timeout is not automatically the same as network failure.
- Network failure: Request could not complete due to a network-related error.
- HTTP failure: Server returned an unsuccessful HTTP status.
- Timeout: Request exceeded the allowed time.
- Cancellation: Application or user requested the operation to stop.
Also, aborting a client-side request does not guarantee that a server has stopped processing an operation that it already received.

No. Once aborted, its signal remains aborted. Create a new controller for a new request.

Yes. You can pass the same signal to multiple supported operations and abort them together.

Q3. What is AbortSignal.timeout()?

It is a built-in API that creates an AbortSignal which automatically aborts after a specified duration in milliseconds.
const response = await fetch("/api/users", {
  signal: AbortSignal.timeout(5000)

It is supported in modern browsers and Node.js versions. Check runtime compatibility when using it in production.

JavaScript: Garbage Collection and Memory Leaks
This is an important topic for a 4+ years React.js / MERN Stack interview, especially when discussing application performance and production issues.

Let's understand it from basics with real project examples.

1. What is Garbage Collection?
Technical definition (interview-ready):

Garbage Collection (GC) is an automatic memory management process in JavaScript that identifies and removes objects that are no longer reachable or needed by the application, freeing memory for future use.

Why do we need Garbage Collection?
When we create variables, objects and arrays, JavaScript uses memory to store their data.

Example:

let user = {
  name: "John",
  age: 25
};

JavaScript allocates memory for this object.

Now:

user = null;

The original object is no longer reachable through user. If nothing else references it, it becomes eligible for garbage collection.

JavaScript's Memory Management Explained | Felix Gerschau
Important: We cannot force JavaScript to immediately remove an object. The garbage collector decides when to reclaim its memory.

2. How does Garbage Collection work?
JavaScript engines such as V8 mainly use a technique called Mark-and-Sweep.

It works in two main steps:

Mark: The engine identifies objects that are reachable from roots, such as global variables and active function execution contexts.

Sweep: Objects that are not reachable are considered garbage and their memory can be reclaimed.

Example
let user = {
  name: "John"
};

let admin = user;

user = null;

Is the object eligible for garbage collection?

No.

Why? Because admin still references the same object.

admin = null;

Now, if there are no other references, the object becomes eligible for garbage collection.

Interview question: What is reachability?

Reachability means whether an object can still be accessed through references starting from the program's active roots.

3. What is a Memory Leak?
Important interview topic
Technical definition (interview-ready):

A memory leak occurs when an application unnecessarily retains references to objects that are no longer needed. Because those objects remain reachable, the garbage collector cannot reclaim their memory.

Why does a memory leak happen?
Consider this example:

const users = [];

function addUsers() {
  for (let i = 0; i < 100000; i++) {
    users.push({
      name: "User " + i
    });
  }
}

addUsers();

Here, we continuously add objects to the global users array.

Even after addUsers() finishes, the objects remain referenced by users.

If the application keeps adding data without removing unnecessary entries, memory usage keeps increasing.

4. Common causes of Memory Leaks in JavaScript
These are particularly important in React and Node.js interviews.

A. Global variables
function processData() {
  window.myData = new Array(1000000).fill("Hello");
}

Because window.myData is globally reachable, its data stays in memory until the reference is removed.

Real use case: Accidentally storing large API responses in global variables.

B. Event listeners not removed
function handleClick() {
  console.log("Button clicked");
}

window.addEventListener("resize", handleClick);

If a component or page no longer needs this listener but never removes it, the listener can remain registered.

Solution:

window.removeEventListener("resize", handleClick);

C. setInterval not cleared
setInterval(() => {
  console.log("Running...");
}, 1000);

If the interval is no longer needed but continues running, it can retain references and waste resources.

Solution:

const timer = setInterval(() => {
  console.log("Running...");
}, 1000);

clearInterval(timer);

D. Closures retaining unnecessary data
function createFunction() {
  const largeData = new Array(1000000).fill("Hello");

  return function () {
    console.log("Hello");
  };
}

const fn = createFunction();

In this particular example, modern JavaScript engines can recognize that largeData is not used by the returned function, so they may optimize away its retention.

A real leak occurs when a long-lived closure actually retains and uses a large object that is no longer needed.

5. Memory Leaks in React.js
This is especially important for your React interview.

Imagine a component that starts an interval.

import { useEffect } from "react";

function Timer() {
  useEffect(() => {
    const timer = setInterval(() => {
      console.log("Timer running");
    }, 1000);

    return () => {
      clearInterval(timer);
    };
  }, []);

  return <h1>Timer</h1>;
}

Why do we use the cleanup function?

When the component unmounts, React executes the cleanup function and clears the interval.

Without cleanup, the timer may continue running even after the component is removed.

Other React examples:

Event listeners not removed.

Subscriptions not unsubscribed.

WebSocket connections not closed.

Timers not cleared.

Long-lived references retaining unnecessary data.

For your WebSocket-based slot game frontend, remember to close or unsubscribe from the WebSocket connection when the relevant component or connection lifecycle ends.

6. Memory Leaks in Node.js
In Node.js, memory leaks can affect the entire backend process.

Example:

const cache = {};

app.get("/users/:id", (req, res) => {
  cache[req.params.id] = {
    data: new Array(10000).fill("User")
  };

  res.send("User added");
});

If requests keep adding new entries and the cache never removes expired or unnecessary data, memory usage can grow continuously.

How to prevent it?

Use cache expiration (TTL).

Remove unnecessary references.

Clean up event listeners.

Monitor memory usage.

Use heap snapshots to investigate leaks.

Yes. JavaScript engines automatically allocate and reclaim memory through garbage collection.

Q2. Can we manually trigger garbage collection?

Normally, no. Garbage collection is controlled by the JavaScript engine. Node.js can expose global.gc() when started with --expose-gc, mainly for testing and diagnostics.

2. Throttling in JavaScript
What is Throttling?
Technical definition (interview-ready):

Throttling is a JavaScript performance optimization technique that ensures a function executes at most once within a specified time interval, even if the event is triggered multiple times.

Why do we use it?
Imagine an application where the user scrolls a page.

While scrolling, the scroll event fires many times.

If we execute a function for every scroll event, it may cause unnecessary work and affect performance.

Using throttling, we can execute the function once every 500 milliseconds.

Example without throttling
window.addEventListener("scroll", () => {
  console.log("Scrolling...");
});

This function may execute many times during scrolling.

Example with throttling
function throttle(callback, delay) {
  let lastTime = 0;

  return function (...args) {
    const currentTime = Date.now();

    if (currentTime - lastTime >= delay) {
      callback.apply(this, args);
      lastTime = currentTime;
    }
  };
}

window.addEventListener(
  "scroll",
  throttle(() => {
    console.log("Scroll event executed");
  }, 500)
);

How does this code work?
lastTime stores the previous execution time.

Whenever the scroll event happens, we get the current time.

We check whether 500ms have passed.

If 500ms have passed, the callback executes.

Otherwise, the callback is ignored.

Real-world use cases
Scroll event handling.

Window resizing.

Mouse movement tracking.

Game controls and frequent user interactions.

Limiting repeated UI updates.

3. Memoization in JavaScript
What is Memoization?
Technical definition (interview-ready):

Memoization is a performance optimization technique in JavaScript that stores the results of previously executed function calls and reuses those results when the same inputs occur again, instead of recalculating them.

Why do we use Memoization?
Imagine you have a function that calculates the sum of two numbers.

function add(a, b) {
  console.log("Calculating...");
  return a + b;
}

console.log(add(10, 20));
console.log(add(10, 20));
console.log(add(10, 20));

Output:

Calculating...
30
Calculating...
30
Calculating...
30
The same calculation happens three times.

With memoization, we can store the result and reuse it.

Example: Memoization
function memoize(fn) {
  const cache = {};

  return function (a, b) {
    const key = `${a}-${b}`;

    if (key in cache) {
      console.log("Getting from cache");
      return cache[key];
    }

    console.log("Calculating...");
    const result = fn(a, b);

    cache[key] = result;

    return result;
  };
}

function add(a, b) {
  return a + b;
}

const memoizedAdd = memoize(add);

console.log(memoizedAdd(10, 20));
console.log(memoizedAdd(10, 20));
console.log(memoizedAdd(10, 20));

Output:

Calculating...
30
Getting from cache
30
Getting from cache
30
What happened?

First call: add(10, 20) calculates the result.

Result 30 is stored in the cache.

Second call: JavaScript checks the cache.

Since the result already exists, it returns 30 without recalculating.

Third call: Same cached result is reused.

4. Memoization in React.js
This is very important for your React interview.

React provides two commonly used APIs related to memoization:

A. useMemo
useMemo caches a calculated value between renders.

import { useMemo, useState } from "react";

function App() {
  const [count, setCount] = useState(0);
  const [number, setNumber] = useState(10);

  const result = useMemo(() => {
    console.log("Calculating...");
    return number * 2;
  }, [number]);

  return (
    <div>
      <h2>Result: {result}</h2>

      <button onClick={() => setCount(count + 1)}>
        Count: {count}
      </button>

      <button onClick={() => setNumber(number + 1)}>
        Change Number
      </button>
    </div>
  );
}

What happens?

When count changes, the component renders again.

But number has not changed, so React can reuse the memoized result.

When number changes, React recalculates the result.

B. React.memo
React.memo helps prevent unnecessary re-rendering of a child component when its props have not changed (using shallow comparison by default).

import React from "react";

const Child = React.memo(function Child({ name }) {
  console.log("Child rendered");

  return <h2>Hello {name}</h2>;
});

export default function App() {
  const [count, setCount] = React.useState(0);

  return (
    <>
      <Child name="John" />

      <button onClick={() => setCount(count + 1)}>
        Count: {count}
      </button>
    </>
  );
}

When the parent updates count, the child can skip rendering because its name prop has not changed.

Important: If you pass a newly created object or function as a prop on every render, shallow comparison may detect it as changed. useMemo and useCallback can help when appropriate.

3. What is Event Delegation?
Technical definition (interview-ready):

Event delegation is a technique in JavaScript where we attach a single event listener to a parent element to handle events triggered by its child elements, using event bubbling.

Why do we use it?
Imagine an e-commerce application with 100 product buttons.

Without event delegation, we might attach 100 individual click listeners.

With event delegation, we attach only one listener to the parent container.

Example without delegation
const buttons = document.querySelectorAll(".product");

buttons.forEach((button) => {
  button.addEventListener("click", () => {
    console.log("Product clicked");
  });
});

Example with delegation
<div id="products">
  <button class="product">Mobile</button>
  <button class="product">Laptop</button>
  <button class="product">Tablet</button>
</div>

document.getElementById("products")
  .addEventListener("click", (event) => {

    if (event.target.matches(".product")) {
      console.log(event.target.textContent);
    }

  });

Output when clicking Laptop:

Laptop
How does it work?

We attach one listener to the parent.

User clicks a child button.

The event bubbles to the parent.

event.target identifies the clicked element.

We handle the click based on the target.

Event Delegation in JavaScript: A Smarter Approach for Efficient Event Handling | by Ahmad | Medium
Real-world use cases
E-commerce product lists.

Dynamic table rows.

Todo lists.

Shopping cart actions.

Dynamically created buttons.

Important interview point: Event delegation also works for dynamically added child elements because the parent listener is already registered.

4. What is DOM Performance?
Technical definition (interview-ready):

DOM performance optimization means reducing unnecessary DOM operations, layout calculations and rendering work to make web applications faster and more responsive.

Why do we need it?
When JavaScript modifies the DOM, the browser may need to recalculate styles, layout and painting.

Too many unnecessary DOM operations can affect performance.

Common optimization techniques
1. Use event delegation

Instead of attaching many listeners to individual elements, use one parent listener where appropriate.

2. Avoid unnecessary DOM updates

Update only the elements that need changes.

3. Use DocumentFragment for bulk DOM insertion

const list = document.getElementById("list");

const fragment = document.createDocumentFragment();

for (let i = 1; i <= 5; i++) {
  const li = document.createElement("li");
  li.textContent = "Item " + i;

  fragment.appendChild(li);
}

list.appendChild(fragment);

This lets you build multiple elements off the live DOM and append them together.

4. Avoid unnecessary layout thrashing

Repeatedly reading layout properties and then changing styles can force repeated layout calculations.

5. Use React efficiently

Avoid unnecessary component renders.

Use stable keys in lists.

Use React.memo, useMemo and useCallback when they provide measurable benefits.

Virtualize very large lists when appropriate.

5. Important 4+ Years Interview Questions
Q1. What is the difference between event.target and event.currentTarget?

event.target: The actual element where the event originated.

event.currentTarget: The element whose event listener is currently executing.

Q2. What is stopPropagation()?

It prevents an event from continuing to propagate to other elements through the capturing or bubbling path.

event.stopPropagation();

Q3. What is the difference between preventDefault() and stopPropagation()?

preventDefault() prevents the browser's default action.

stopPropagation() stops event propagation.

Example: preventDefault() can prevent a form from submitting normally.

Q4. Why is event delegation useful?

It reduces the number of event listeners and makes handling dynamically added elements easier.

Q5. Does every event bubble?

No. Some events, such as focus and blur, do not bubble normally. Their bubbling alternatives are focusin and focusout.

1. Web Workers
What are Web Workers?
Technical definition (interview-ready):

Web Workers are a browser feature that allows JavaScript to execute scripts in a background thread, separate from the main thread, without blocking the user interface.

Why do we use Web Workers?
Normally, JavaScript running in the browser executes on the main thread.

The main thread handles:

UI rendering.

Button clicks.

User interactions.

DOM updates.

JavaScript execution.

Imagine your application needs to process 1 million records. If you perform a heavy calculation on the main thread, the UI may freeze.

Web Workers allow heavy calculations to run in a separate background thread.

Boosting React App Performance with Web Workers and Offloading Tasks | by Abhishek Pragada | Medium
Example without Web Worker
function heavyCalculation() {
  let total = 0;

  for (let i = 0; i < 1000000000; i++) {
    total += i;
  }

  console.log(total);
}

heavyCalculation();

This calculation blocks the browser's main thread while it runs.

Example with Web Worker
Step 1: Create worker.js

self.onmessage = function (event) {
  let total = 0;

  for (let i = 0; i < 1000000000; i++) {
    total += i;
  }

  self.postMessage(total);
};

Step 2: Main JavaScript file

const worker = new Worker("worker.js");

worker.postMessage("start");

worker.onmessage = function (event) {
  console.log("Result:", event.data);
};

How does it work?
Main thread creates a Worker.

Main thread sends a message using postMessage().

Worker performs the heavy calculation in the background.

Worker sends the result back using postMessage().

Main thread receives the result through onmessage.

Important: Web Workers cannot directly access or manipulate the DOM. They communicate with the main thread through messages.

Real React project use cases
Processing large Excel or CSV files.

Image processing.

Large data calculations.

Complex game calculations.

Parsing large datasets.

For example, in your slot game frontend, a Web Worker could handle expensive calculations or data processing without freezing the game UI.

Interview question: What is the difference between Web Workers and the main thread?

Answer:

"The main thread handles UI rendering and user interactions, whereas Web Workers execute JavaScript in a separate background thread. They communicate using message passing and help prevent heavy computations from blocking the UI."

Example 1: O(1) – Constant time
function getFirst(arr) {
  return arr[0];
}

console.log(getFirst([10, 20, 30]));

We access only one element, regardless of array size.

Time complexity: O(1)

Example 2: O(n) – Linear time
function printNumbers(arr) {
  for (let i = 0; i < arr.length; i++) {
    console.log(arr[i]);
  }
}

If there are 10 elements, the loop runs 10 times.

If there are 1,000 elements, it runs 1,000 times.

Time complexity: O(n)

Example 3: O(n²) – Quadratic time
function printPairs(arr) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = 0; j < arr.length; j++) {
      console.log(arr[i], arr[j]);
    }
  }
}

If there are 3 elements:

Outer loop: 3 times.

Inner loop: 3 times for each outer iteration.

Total: 9 iterations.

If there are 100 elements, total iterations are 10,000.

Time complexity: O(n²)

Real MERN project use cases
Optimizing product search.

Filtering large user lists.

Improving API data processing.

Avoiding unnecessary nested loops.

Optimizing sorting and searching algorithms.

Interview question: What is the difference between O(n) and O(n²)?

Answer:

"O(n) means execution time grows linearly with input size, whereas O(n²) means execution time grows quadratically. Nested loops over the same input commonly result in O(n²), so I try to avoid unnecessary nested iterations when processing large datasets."

3. XSS Basics
Important security topic
What is XSS?
Technical definition (interview-ready):

Cross-Site Scripting (XSS) is a security vulnerability in which an attacker injects malicious scripts into a trusted website, causing those scripts to execute in another user's browser.

Why do we need to understand XSS?
Imagine you are building a social media application.

Users can submit comments.

An attacker submits malicious HTML and JavaScript instead of normal text.

If your application displays that content unsafely, the attacker's script may execute in other users' browsers.

Example of an XSS attack
Imagine an attacker submits:

<script>
  alert("Your account is hacked!");
</script>

If your application inserts this as executable HTML, the browser may run the script.

XSS (Cross-Site Scripting) Explained: How It Works & How to Stop It
Types of XSS
1. Stored XSS

Malicious script is saved in the database and executed whenever users view the affected content.

Example: An attacker stores a malicious comment in a database.

2. Reflected XSS

Malicious input is included in a server response and executed by the browser.

Example: An unsafe search page reflects attacker-controlled query parameters into HTML.

3. DOM-based XSS

The vulnerability occurs when client-side JavaScript takes untrusted input and inserts it into the DOM unsafely.

Example:

const params = new URLSearchParams(location.search);
const name = params.get("name");

document.getElementById("output").innerHTML = name;

If name contains malicious HTML, it may execute.

How do we prevent XSS in React?
1. Use React's default escaping

function UserComment({ comment }) {
  return <p>{comment}</p>;
}

React escapes text values rendered through JSX, so HTML entered as text is not executed.

2. Avoid unsafe dangerouslySetInnerHTML

<div dangerouslySetInnerHTML={{ __html: userInput }} />

Avoid inserting untrusted HTML this way. If rich HTML is required, sanitize it with a trusted HTML sanitizer.

3. Sanitize untrusted HTML

For example, DOMPurify can sanitize HTML before rendering it.

4. Use Content Security Policy (CSP)

CSP helps restrict which scripts the browser is allowed to execute.

5. Use secure cookie settings

For authentication cookies, use appropriate HttpOnly, Secure and SameSite settings. HttpOnly prevents JavaScript from reading the cookie, but it does not by itself prevent XSS.

Real MERN project use cases
User comments and reviews.

Chat messages.

Rich text editors.

User profile descriptions.

Search result pages.

Admin dashboards displaying user-generated content.

Interview questions
Q1. What is the difference between Stored XSS and Reflected XSS?

Stored XSS saves malicious content on the server, whereas Reflected XSS returns malicious input immediately in a response.

Q2. Does React prevent XSS automatically?

React escapes values rendered as text through JSX by default. However, unsafe HTML insertion, third-party scripts and other insecure DOM operations can still introduce XSS vulnerabilities.

Q3. What is dangerouslySetInnerHTML?

It is a React property that allows developers to insert raw HTML into the DOM. It should only be used with trusted or properly sanitized HTML.

Q4. What is CSP?

Content Security Policy is a browser security mechanism that controls which resources, especially scripts, are allowed to load and execute.
